# Диагностика и FAQ

## Где лежат логи

- **Приложение**: меню → экспорт лога → «передать» (интенты) или «сохранить» (Загрузки). Крэшлоги также пишутся в Загрузки.
- **Интеграция**: Настройки HA → Система → Журналы; фильтр по `diplus2hass`.

Включите **Настройки → Подробный лог** в приложении для детализации команд и ответов.

## Частые проблемы

### Интеграция не стартует: `ImportError: cannot import name ... from '...const'`

Смешанная установка: часть файлов от старой версии, часть от новой. **Решение:** удалите `/config/custom_components/diplus2hass/` полностью, скопируйте папку из свежего zip, перезапустите HA.

### `The unit of sensor.* cannot be converted ...`

Сменилась единица измерения у сенсора со статистикой. **Решение:** обновите интеграцию до v2.1.0+ (стабильные единицы), затем Developer Tools → Statistics → у проблемных сенсоров нажмите «Fix issue» и удалите старую статистику. Long-term statistics возобновятся.

### Нет данных в HA, но приложение работает

1. Проверьте **Отправлять в HA** на главном экране приложения.
2. Проверьте адрес, токен и имя автомобиля (**Проверить соединение** в настройках).
3. Имя авто должно совпадать с именем интеграции **точно** (регистр важен).
4. Посмотрите `binary_sensor.<авто>_online` — если `off`, приложение не шлёт данные: сеть ГУ, HTTPS, токен.

### Команды из HA не выполняются

1. Включено ли **Управление авто из HA** в настройках приложения?
2. Команды ставятся в очередь — задержка до нескольких секунд нормальна.
3. Если авто офлайн, команда ждёт таймаут и удаляется.
4. В журнале приложения (вкладка Команды) видна верификация: `ожидалось/фактически`.

### Окно не дошло до заданного процента

Механика окон медленная, DiPlus подтверждает команду сразу. Верификация покажет «несоответствие» с фактическим значением — повторите команду, обычно доводит до цели.

### Приложение не работает при выключенном авто

Нужен [фоновый режим](../app/background.md): включите настройку, подтвердите ADB-разрешение, при необходимости выполните ADB-команды вручную. На части прошивок система всё равно усыпляет приложение — ограничение DiLink.

### Правило сработало «само» при старте авто

Обновитесь до v2.1.0+: движок правил пропускает тики с пустым кэшем сенсоров и помнит состояние между поездками. Если правило «честное» (например, тормоз нажат при запуске) — увеличьте кулдаун или включите «один раз за поездку».

### Спам `Untranslated value for geo_*` в логах

Исправлено в v2.1.0 — виртуальные датчики геозон больше не пишут предупреждения. Обновите приложение.

### Геозона не срабатывает

1. Разрешения на геолокацию (в т.ч. фоновую) выданы?
2. Есть ли живые координаты (статус GPS в верхней строке)?
3. Радиус зоны не слишком мал? GPS на стоянке «дрожит» на десятки метров — ставьте ≥ 50–100 м.

## Известные ограничения

- Часть сигналов зависит от комплектации и прошивки авто — неподдерживаемые помечаются автоматически.
- Каналы связи: приложение → HA — HTTP(S) push; HA → приложение — опрос очереди; команды авто — через локальный API DiPlus (127.0.0.1:8988).
- Если DiPlus убит системой, данных не будет: держите его в автозапуске вместе с нашим приложением.
