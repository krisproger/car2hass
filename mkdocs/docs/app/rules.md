# Правила

Движок правил — локальные автоматизации прямо на головном устройстве. Home Assistant не нужен: условия проверяются каждую секунду, действия выполняются через DiPlus.

## Как работает правило

Правило = **условия** + **действия** (+ опционально **действия «иначе»**).

- **Условие** — сравнение сенсора со значением: `=`, `≠`, `>`, `<`, `≥`, `≤`. Условий может быть несколько, они объединяются связками **AND** / **OR**, у каждого есть флаг **NOT** (инверсия).
- **Действие** — команда из [каталога](commands.md) с параметром (или без). Действий может быть несколько — выполняются последовательно.
- **«Иначе» (else)** — отдельный набор действий, выполняемый когда условие переходит в «ложь».

Примеры:

- Температура на улице > 25 °C **и** на сиденье есть пассажир → включить обдув сиденья.
- Коробка в `P` → открыть двери; коробка в `D` → закрыть двери.
- Время 08:00 **и** на улице < −10 °C → подогрев сидений.
- Вход в [геозону](geofences.md) «дом» → включить свет в салоне.

!!! note "Пустое значение у условия геозоны"
    Если у условия с `geo_*` сенсором значение не задано, оно трактуется как `inside` — правила, сохранённые без значения, продолжают работать. Для условий «снаружи» укажите значение `outside` явно.

## Флаг «Изменение»

У каждого условия есть флаг **«Изменение»**: если он отмечен хотя бы у одного условия, правило срабатывает **по переходу этого сенсора** из «ложь» в «истину», а не когда условие просто истинно. Остальные условия в этот момент выступают **гардами** — проверяются, но сами правило не запускают.

Пример «открыть двери на паркинге»: отметьте «Изменение» у условия `gear = P` и сохраните — правило сработает один раз при переключении в `P`. Повторное «перещёлкивание» гарды (например, двери снова заперлись после действия) не вызовет повторного срабатывания.

## Параметры правила

| Параметр | По умолчанию | Описание |
|----------|--------------|----------|
| Включено | да | выключенные правила не проверяются |
| По фронту | да | срабатывать только при переходе условия из «ложь» в «истину» (для else-ветки — из «истина» в «ложь»). Если выключено — срабатывает на каждой секундной проверке (с учётом кулдауна) |
| Один раз за поездку | нет | после срабатывания правило молчит до следующей сессии движка |
| Мин. интервал, с | 1800 | кулдаун между срабатываниями — **только для уровневых правил** (по фронту = выкл). Для правил по фронту кулдаун не нужен: фронт сам ограничивает срабатывания (в редакторе поле отмечено серым) |
| Удерживать условие, с | 0 | условие должно держаться истинным N секунд подряд перед срабатыванием — защита от флапа сигнала (0 = сразу) |
| Анти-зацикливание, с | 60 | окно, в котором одинаковая команда с тем же значением не отправляется повторно — защита от «щёлканья» двух правил туда-сюда |

В списке правил у каждого видно время последнего срабатывания — отдельно для прямой и else-ветки («сработало: 25.07 08:12»).

!!! note "Почему у правил по фронту нет кулдауна"
    До версии 2.1.1 30-минутный кулдаун применялся ко всем правилам, и «открыть двери на паркинге» срабатывало раз в полчаса вместо каждого паркинга на коротких поездках. С v2.1.1 правила по фронту стреляют на каждом переходе; анти-зацикливание (60 с) остаётся как защита от петель.

## Защита от ложных срабатываний

- **Восстановленные значения пропускаются** — пока сенсор хранит только значение прошлой сессии (восстановленное при старте), правило не срабатывает до прихода живых данных.
- **Пустые значения пропускаются** — если сенсор ещё не дал значения, правило пропускается (нет срабатываний «на пустом месте»).
- **Первый тик после старта** — первая оценка условия в сессии только запоминает состояние и никогда не считается фронтом: правило не стреляет сразу при запуске.
- **Персистентное состояние** — движок помнит последнее значение условия каждого правила между перезапусками: правило по фронту не сработает на старте, если состояние не менялось.
- **Кулдаун и анти-зацикливание** — см. таблицу выше.

## Редактор правил

- Условия и действия — строками; кнопки добавления, удаления и перестановки ↑/↓.
- Сенсор и оператор — списками; названия сенсоров локализованы (200 шт., EN/RU).
- **Значение условия** — автодополнение из реально наблюдавшихся значений сенсора (числовые отсортированы по величине).
- **Значение действия** — автодополнение по типу команды: для перечислений — локализованные варианты, для чисел — диапазон `min..max` и ранее использованные значения; для команд без параметра поле отключено.

## Кнопка «Тест»

В редакторе правил есть кнопка **«Тест»** — проверка правила без автомобиля:

- По каждому условию показываются фактическое значение сенсора, оператор, ожидаемое значение и результат (✓/✗), а также общий результат группы.
- Значения сенсоров можно **подменить вручную** (и вернуть к живому значению), чтобы проверить правило при нужных условиях.
- Команды при тесте **не выполняются** — это чистая диагностика.

## Экспорт и импорт

В меню правил: экспорт в файл или буфер обмена, импорт из файла/буфера. Формат v2 (принимает и старый v1). Экспорт общей конфигурации приложения включает правила и [геозоны](geofences.md) вместе с настройками подключения.

## Примеры при первом запуске

На новой установке создаются пять выключенных правил-шаблонов (на языке системы): обдув сидений при жаре, проветривание, открытие дверей на паркинге, подогрев при морозе. Включите нужные и подстройте под себя.
