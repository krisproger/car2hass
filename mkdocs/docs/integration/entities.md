# Сущности интеграции

Интеграция создаёт сущности с префиксом имени автомобиля, заданным при добавлении (ниже — `bydsongpro` как пример).

## Сенсоры `sensor.*`

Числовые и текстовые сигналы телеметрии — более 130: скорость, запас хода, SOC, температуры, напряжения, пробег, режимы, версии ПО и т.д.

- Числовые сенсоры имеют `state_class: measurement` — доступны для графиков и long-term statistics.
- Единицы измерения стабильны (км/ч, %, °C, мм и т.д.) — не меняйте их в настройках сущности, иначе статистика потребует сброса.
- Текстовые (enum) сенсоры показывают локализованные значения: `P/R/N/D`, режимы движения, состояние зарядки и т.п.

Служебные сенсоры:

| Сенсор | Описание |
|--------|----------|
| `sensor.bydsongpro_app_version` | версия Android-приложения на ГУ |
| `sensor.bydsongpro_ui_config_version` | версия конфигурации пресетов |
| `sensor.bydsongpro_wifi_*` | параметры текущей Wi-Fi сети ГУ |

## Бинарные сенсоры `binary_sensor.*`

Формируются из enum-значений по карте «истинных» состояний: двери (`open` → on), замки (`locked` → on), ремни, свет, климат, зарядка (`Ready/started/charging/full` → on), поворотники, `online` (связь с авто) и др.

## Трекер `device_tracker.bydsongpro`

Местоположение автомобиля: координаты, скорость, время фиксации. Работает при выданных приложению разрешениях на геолокацию.

## Геозоны `binary_sensor.*_geofence_*`

Каждая [геозона](../app/geofences.md), созданная в приложении, автоматически появляется как бинарный сенсор:

```
binary_sensor.bydsongpro_geofence_<название_зоны>
```

`on` — автомобиль внутри зоны (класс presence). Имя сущности формируется при первом появлении зоны; после переименования зоны в приложении перезагрузите интеграцию.

## Сенсор связи

`binary_sensor.bydsongpro_online` — «авто на связи»: приложение присылает признак жизни; при пропадании обновлений дольше таймаута сенсор переходит в `off`. Используйте его условием в автоматизациях, чтобы не слать команды на недоступный автомобиль.

## Обновление данных

Приложение присылает снапшот каждые несколько секунд (пока включена передача). Интеграция обновляет сущности сразу по приходу пакета (local push). При потере связи приложение копит данные в [очереди](../app/settings.md) и догружает после восстановления связи — история в HA не теряется.

Каждый снапшот пакета несёт собственную метку времени. На Home Assistant **2024.6+** интеграция записывает промежуточные значения в историю с этими метками (`hass.states.async_set(..., timestamp=...)`), поэтому графики показывают фактическую траекторию изменений — в том числе догруженной из очереди — а не один момент обработки пакета. На более старых версиях HA промежуточные значения записываются текущим временем, как и раньше.
