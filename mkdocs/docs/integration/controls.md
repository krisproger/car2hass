# Управление из Home Assistant

Элементы управления появляются в HA, когда в приложении включено **Настройки → Управление авто из HA**. Команды ставятся в очередь в интеграции, приложение забирает их при опросе и выполняет через DiPlus с [верификацией](../app/commands.md#проверка-выполнения-верификация) по сенсорам.

!!! warning "Безопасность"
    Управление выключено по умолчанию. Включайте, только если доверяете своей сети и токенам: любой, кто получит доступ к HA, сможет управлять автомобилем.

## Типы элементов

| Платформа | Что делает | Примеры |
|-----------|-----------|---------|
| `switch` | бинарные команды вкл/выкл | климат, фары, детские замки, ADB |
| `number` | числовые параметры | температура климата (16–30), скорость вентилятора (1–9), громкость (0–100), целевой SOC |
| `select` | выбор из вариантов | режим движения (ECO/SPORT/NORMAL/SNOW), HEV/EV/Force EV, направление обдува, рециркуляция |
| `button` | разовые действия | закрыть все окна, проветрить, ± громкости/вентилятора/температуры, открыть багажник |
| `lock` | центральный замок | lock/unlock по реальному состоянию замков |
| `climate` | климат как HVAC-объект | вкл/выкл, целевая температура, вентилятор |
| `alarm_control_panel` | режим «сентри» | arm/disarm охранного режима |

## Связь команд и сенсоров

Элементы управления связаны с сенсорами через [реестр соответствия](../advanced/ota.md): например, `number` температуры климата отображает текущее значение сенсора `ac_set_temp` и обновляется, если температуру изменили с экрана автомобиля. Поэтому в HA всегда видно реальное состояние, а не только последняя отправленная команда.

## Очередь команд

- Команды дедуплицируются: повторная такая же команда в очереди заменяет предыдущую.
- Устаревшие команды (не забранные приложением за таймаут) удаляются.
- Если авто офлайн (`binary_sensor.*_online` = off), команды дождутся появления связи в пределах таймаута.

## Пример автоматизации

```yaml
automation:
  - alias: "Прогрев по расписанию"
    trigger:
      - platform: time
        at: "07:30:00"
    condition:
      - condition: numeric_state
        entity_id: sensor.bydsongpro_outside_temp
        below: -5
      - condition: state
        entity_id: binary_sensor.bydsongpro_online
        state: "on"
    action:
      - service: climate.turn_on
        target:
          entity_id: climate.bydsongpro
      - service: climate.set_temperature
        target:
          entity_id: climate.bydsongpro
        data:
          temperature: 22
```

## Локальные правила как альтернатива

Для автоматизаций, которые должны работать без связи с HA (подземный паркинг, нет сети), используйте [движок правил](../app/rules.md) в самом приложении.
