# История версий

> **Скачать актуальное приложение Android:** <https://mytechnic.ru/cartelemetry/download.php?file=app>

## v3.0.29 (текущая)

- Редактор карточки cartelemetry-vehicle-card: HA теперь показывает кастомный редактор
  с настройкой позиций иконок (x/y) и ссылкой на свою картинку (image_url).

## v3.0.28

- OBD: канал теперь определяется «живым» сразу после ATI; анализ протокола (ATDP) и
  опрос поддерживаемых PID идут в фоне — исследование больше не убивает probe по таймауту.
- Все типы плиток дашборда (в т.ч. громкость/пресеты с зонами) приведены к единому виду:
  бирюзовая окантовка + фиксированная высота. Цвета в коде переведены на атрибуты темы.

## v3.0.27

- Исправлено: включение протокола OBD (чекбокс или кнопка подключения) реально включает его —
  раньше флаг isObdEnabled не выставлялся, поэтому канал OBD был недоступен даже при
  отмеченном чекбоксе и успешном подключении адаптера.

## v3.0.26

- Главный экран: под полоской очереди зарезервировано место — при появлении очереди экран
  больше не сдвигается.
- Плитки дашборда: фиксированный размер (150dp), без лишних отступов, светлобирюзовая
  окантовка. Цвета вынесены в палитру (основа для тем оформления).

## v3.0.25

- В probe-report (исследование) добавлен блок «diagnostics»: состояние OBD (включён ли,
  режим, статус, протокол ATDP, число поддерживаемых PID, последняя ошибка, имя/MAC адаптера).
  По любому исследованию на сервере сразу видно, почему OBD-канал недоступен.

## v3.0.24

- У карточки cartelemetry-vehicle-card появился визуальный редактор: настройка позиций
  иконок (x/y в % от картинки) для сенсоров/дверей/кнопок + ссылка на свою картинку (image_url).

## v3.0.23

- В экспорт/отправку журнала добавлен блок «Диагностика»: профиль, активные каналы, VVIN/прошивка,
  состояние OBD (статус, протокол ATDP, число поддерживаемых PID, последняя ошибка).
- Для телефонов без DiPlus/Voyah: авто-определение сопряжённого ELM327-адаптера (если адрес
  не выбран) и подсказка в исследовании «подключите OBD-адаптер».

## v3.0.22

- OBD-II: автоматическое подключение к адаптеру при исследовании/запуске; на кнопке OBD
  живой статус «подключено / нет связи».
- Анализ протокола при подключении (ELM327 init, ATDP) и опрос bitmap поддерживаемых PID —
  читаются только универсальные стандартные показатели, которые поддерживает конкретный авто.

## v3.0.21

- Добавлена вторая карточка **`custom:cartelemetry-vehicle-card`**: силуэт
  авто/грузовика/мотоцикла, сенсоры и кнопки по binding-точкам, спидометр,
  панели сенсоров/управления/дверей. Изображения CC0 в `assets/`. Работает рядом
  с прежней карточкой (не ломает её).

## v3.0.20

- Исправлено: сенсоры/управление теперь принадлежат устройству автомобиля (device_info
  возвращал None — сущности были без устройства). После перезагрузки сущности группируются
  в устройство авто + связанный трекер.

## v3.0.19

- Исправлено: генератор const.py терял ручную константу `ONLINE_OFFLINE_SECONDS`
  (интеграция не стартовала — «cannot import name»). Теперь константа пишется генератором.

## v3.0.18

- Voyah: набор сенсоров расширен с 3 до **29** — курируемые параметры из прошивки
  (фары/туманки, тормоз/акселератор, зарядка, дворники, двери/замки, климат, режим движения).
- Добавлены новые сенсоры для автоматизаций: подогрев/вентиляция сидений (перед/зад),
  подогрев руля, обогрев заднего стекла, мощность зарядки, складывание зеркал.
- Все они пробуются в исследовании и читаются каналом Voyah (на реальном авто — те,
  что реально отдаёт сервис).

## v3.0.17

- Voyah: расширен набор сенсоров из прошивки (powertrain_mode, low_beam, DRL) — теперь 6.
- Исследование: в сводке «Сенсоров по каналам» видно, сколько прочитал каждый канал
  (в т.ч. voyah/obd, даже если 0) — понятно, что все каналы пробовались.
- Подсказка в мануале: если ни DiPlus, ни Voyah не дали данных — проверьте, что DiPlus запущен.

## v3.0.16

- Обновление через приложение: установщик теперь находит реальный скачанный APK (на ГУ Voyah
  система сохраняет файл как `*.bin` или без расширения) — обновление работает на Voyah.
- OBD-II: добавлен полный стандартный набор mode-01 — нагрузка двигателя, температура впуска,
  MAF, уровень топлива, температура снаружи/масла, расход топлива (11 PID). Исследование теперь
  пробует их, а OBD-канал читает на любом совместимом авто.

## v3.0.15

## v2.4.0

- **Новая архитектура телеметрии и исследования** — JSON-реестры сенсоров/команд/профилей (141 сенсор / 29 команд / 3 профиля авто), ProbeEngine с автоопределением типа авто по скору ответов сигналов (полный прогон при первом запуске и каждый 3-й запуск, лёгкая проверка каналов между ними) и SourceManager, который централизованно решает, откуда читать, по реестру, активным каналам и отчёту исследования; system-сенсоры (GPS/устройство) читаются всегда.
- **GPS 1 Гц** — координаты/скорость/азимут снимаются каждую секунду и передаются батчами окном ~4 с; GPS-минимум присутствует в интеграции всегда.
- **Секция настроек «Исследование системы»** — выбор типа авто из `car_profiles.json`, чекбоксы каналов с доступностью из отчёта, статус исследования и экспорт `probe_report.json`.
- **Анонимные отчёты исследования (опционально, выключено по умолчанию)** — PHP-приёмник на сайте (`/api/probe-report`) с валидацией схемы и rate-limit; MCP-API (`/api/mcp`: `list_car_profiles`, `signal_availability`, `channel_availability`, `raw_reports`) для анализа доступности сигналов/каналов по моделям.
- **Новые каналы** — OBD-II ELM327 по TCP/WiFi (опционально, выключен по умолчанию), честные availability-пробы DiPlus Push и BYD Cloud, Voyah (только чтение) через рефлексию к вендорскому CANBus-сервису.

## v2.3.1

- **Фикс пропадания сенсоров из телеметрии** — DiPlus при обвале сервера больше не помечает исправные сигналы как «неподдерживаемые» (ошибка соединения не считается свойством сигнала). Ранее после обвала DiPlus до 130 сенсоров (включая `window_rr` / `sunroof` / `sunshade`) навсегда прятались из телеметрии; группа «известно неподдерживаемых» сигналов периодически пере-изолируется, чтобы вернувшиеся сигналы снова стали активными.
- **Настройки** — иконки разделов в одну строку с названием (слева); «Протоколы» → «Сервисы / источники данных», «Технические» → «Опции»; «Геозоны» — отдельный пункт левой колонки; язык, «Обновить пресеты» и импорт/экспорт конфигурации перенесены в «Опции», секция «Прочее» убрана.
- **Исследование каналов** — модальное окно с прогресс-баром на время зондирования.
- **Анализ логов** — разбор сценария пропадания сенсоров на BYD Song Pro 2022 задокументирован в `info/telemetry_signal_disappearance_analysis.md`.

## v2.3.0

- **Профиль автомобиля** — производитель (BYD / «Универсальный авто с Android»), марка/модель и год выпуска в настройках; VIN и версия ПО снова попадают в телеметрию (ранее исключались из слияния сенсоров).
- **«Исследование каналов» для универсального авто** — зондирование DiPlus, ADB, системных свойств и экспериментальных каналов с отчётом (экран + лог + файл `research_*.txt`); отчёт прикладывается к отправляемому логу.
- **Настройки переработаны** — левая колонка разделов (Авто / Протоколы / Умный дом / Технические / Прочее), «О программе» открывается модальным окном.
- **Первый запуск новой версии** — автоматически открываются настройки автозапуска и окно «О программе».
- **Нативная запись команд (бета)** — команды применяются через прямой канал записи autoservice (`service call autoservice 6`, тот же setInt, что использует HelperDaemon BYD) в дополнение к DiPlus HTTP. Карта команд в `assets/native_commands.json` сопоставляет команду с адресами; native и DiPlus взаимно подменяют друг друга, так что команда выполняется, пока жив хотя бы один интерфейс. Режим `auto` запоминает, какой интерфейс отвечал последним.
- **Верификация записи и отчёт об интерфейсе** — результат команды включает использованный интерфейс (`native`/`diplus`) и число фоллбэков; запись, принятая интерфейсом, не показывается как ошибка, даже если связанный сенсор недоступен или не подтвердил значение.
- **Чистка native-телеметрии** — `passenger_seatbelt` (мигающий fid) и `trunk` (не читающийся fid) убраны из native-карты чтения; оба продолжают работать через DiPlus.
- **Интервал телеметрии 7 с** — цикл native-чтения (4,5–5,5 с) больше не гоняется со следующим тиком; пропуски циклов (до ~120/сессию) устранены.

## v2.2.0

- **Нативная телеметрия (бета)** — чтение сигналов напрямую с ГУ через on-device ADB (`service call autoservice`), в обход сервера DiPlus. Источник выбирается в настройках (`diplus`/`native`/`auto`); debug-режим сравнивает native-значения с DiPlus в логе.
- **Выверка таблицы команды→сенсоры** — `expectedValue` приведены к фактическим enum-переводам, устранены ложные `state mismatch` для команд дверей/окон/замков/багажника/климата/света.

## v2.1.6

- **Фикс загрузки интеграции** — бинарные сенсоры больше не падают с `ImportError: cannot import name 'ONLINE_OFFLINE_SECONDS'`; порог онлайн/офлайн задан в `const.py` (60 с).
- **Диапазоны команд приведены к реальным возможностям DiPlus** — температура кондиционера 17–30 (дроби отвергаются, иначе DiPlus открывает NaviActivity), вентилятор 1–7, SOC 15–70, внешняя громкость 0–99.
- **Сигналы num → enum** — `sentry_state`, `parked_recording_switch`, `parked_sentry_alarm`, `lead_car_start_state` переведены в перечисления с нормальными метками.
- **История сущностей с реальными метками времени** — пакеты телеметрии реплеятся в recorder HA по времени сбора каждого снапшота (HA 2024.6+): история показывает фактическую траекторию, а не один тик.
- **Запоминание параметров пресетов** — проценты окон, температура/обдув климата сохраняются; диалог редактирования пресета предлагает «Сохранить» / «Сохранить и применить» и не выполняет команды молча.
- **Диалоги действий пресетов — сетка кнопок** — вместо списка; у пресета «Окна» кнопки Закрыть / Открыть (4 стекла на 100 %) / Проветрить / Свои значения.
- **Пресеты дашборда v4** — порт зарядки больше не «отключён» на подключённом пистолете (truthy покрывает реальные значения AC/DC-пистолета и `Ready`); режим охраны стал пресетом с 3 кнопками-действиями; детские замки объединены в одну плитку с 4 действиями; удалён дубль-пресет «Закрыть окна»; «Вентилятор климата» и «Темп. климата» переименованы; сравнение опций select нормализовано (без учёта `_ / + : -` и пробелов).
- **Сенсор зарядки в HA** — бинарный сенсор зарядки включается на `Ready/started/charging/full` (раньше машина на активной зарядке присылала `Ready` и сенсор оставался выключенным).
- **Дедупликация экспорта лога** — повторные timestamp-строки из секций «In-memory» и «Persistent File» больше не дублируются.
- **Единый источник версии** — тест согласованности следит, чтобы версия приложения и интеграции совпадала везде; AndroidManifest очищен от устаревшей версии.
