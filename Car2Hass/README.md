# DiPlus-to-hass

Android-приложение для головного устройства BYD (DiLink), которое читает телеметрию автомобиля через приложение **DiPlus** (обязательно — без него приложение не работает) и отправляет её в **Home Assistant**.

## Возможности

- **132 сигнала** BYD: скорость, SOC, батарея, климат, двери, замки, свет, ADAS и др.
- **Движок правил** — локальные автоматизации: условия AND/OR/NOT, действия «иначе» (else), режим «один раз за поездку», состояние условий сохраняется между поездками.
- **Геозоны** — зоны на карте OpenStreetMap (osmdroid) с кругом радиуса и ручным вводом координат; каждая зона — виртуальный датчик `inside`/`outside` для правил.
- **Дашборд с пресетами** — настраиваемые плитки: переключатели, зоны ➖/➕ (громкость, вентилятор, температура), выбор режимов, агрегированные статусы; пресеты локализованы и обновляются по воздуху (OTA).
- **Foreground Service** — сбор данных продолжается в фоне и после закрытия UI.
- **BootReceiver** — автозапуск сервиса после перезагрузки, если отправка в HA включена.
- **Batch-чтение** сигналов с минимальной нагрузкой на ГУ.
- **Локальный буфер** — при отсутствии сети снапшоты сохраняются в файл и отправляются позже.
- **GPS** — координаты передаются в HA как `device_tracker`.
- **HTTPS** — опциональная защищённая отправка на Home Assistant.
- **Двуязычный UI** — английский и русский, включая редактор правил и пресеты дашборда.
- **Полный экспорт конфигурации** — настройки + правила + геозоны одним JSON-файлом.

## Архитектура

```
BYD ГУ (DiLink)
├─ DiPlus (обязательное приложение)
└─ DiPlus-to-hass
    ├─ TelemetryService (foreground)
    ├─ CANDataReader → DiPlus
    ├─ HassClient → POST /api/byd_diplus
    └─ MainActivity (UI)

Home Assistant
└─ custom_components/diplus2hass
    ├─ REST endpoint /api/byd_diplus
    ├─ sensor
    ├─ binary_sensor
    └─ device_tracker
```

## Сборка

Требуется Android SDK (platform `android-35`, build-tools `36.1.0`) и JDK 17.

```bash
cd DiPlus-to-hass
./build_apk.sh
# APK: build/DiPlus-to-hass.apk
```

Переменные окружения для сборки:

```bash
export ANDROID_SDK=/opt/AndroidStudio/Android/sdk
export BUILD_TOOLS_VERSION=36.1.0
export PLATFORM_VERSION=android-35
./build_apk.sh
```

Для release-сборки укажите собственный keystore:

```bash
export KEYSTORE_FILE=/secure/path/release.jks
export KEYSTORE_PASS=...
export KEY_ALIAS=...
export KEY_PASS=...
./build_apk.sh
```

Если переменные не заданы, скрипт использует dev-keystore из `.keys/dev-release.jks`
(он создаётся автоматически при первой сборке и **не** попадает в git).

Для release-сборки передайте `BUILD_TYPE=release`:

```bash
BUILD_TYPE=release ./build_apk.sh
```

## Установка

> **Важно:** DiPlus-to-hass не работает без установленного и запущенного приложения **DiPlus** на головном устройстве BYD.

```bash
adb install -r DiPlus-to-hass/build/DiPlus-to-hass.apk
```

## Настройка

1. Убедитесь, что **DiPlus** установлен и запущен на ГУ.
2. Откройте DiPlus-to-hass, разрешите доступ к местоположению и уведомлениям.
3. Нажмите ⚙ → **Настройки Home Assistant**.
4. Укажите адрес сервера, порт, Long-Lived Access Token.
5. Включите **Отправлять данные в HA** (и опционально **HTTPS**).
6. Имя автомобиля генерируется автоматически, можно изменить вручную. Имя должно совпадать с именем, заданным в интеграции Home Assistant.

## Устранение неполадок

| Симптом | Причина / решение |
|---|---|
| "diplus not responding" | Запустите DiPlus. DiPlus-to-hass попытается запустить его автоматически, но на некоторых прошивках это невозможно без ручного запуска. |
| Нет данных в HA | Проверьте имя автомобиля в приложении и в интеграции HA — они должны совпадать. |
| Точка на карте не обновляется | Убедитесь, что даны разрешения на местоположение и ГУ получает GPS/сетевую геолокацию. |

## Home Assistant

Скопируйте папку `custom_components/diplus2hass` в конфигурационную директорию HA:

```bash
cp -r custom_components/diplus2hass /config/custom_components/
```

Перезапустите HA и добавьте интеграцию **DiPlus-to-hass — BYD Vehicle Telemetry** через UI.

## Протокол и реестр сигналов

Приложение не читает шину напрямую — данные предоставляет приложение **DiPlus**, установленное на ГУ (обязательно: без него DiPlus-to-hass работать не будет).

### Реестр сигналов

- Приложение получает через DiPlus набор из **132 сигналов** и мапит их на стабильные английские ключи, которые ожидает интеграция Home Assistant (`speed`, `soc`, `driver_door`, `charging_state` и т.д.).
- Набор доступных сигналов зависит от прошивки автомобиля: приложение использует те, что подтверждаются на конкретном авто.
- Полный каталог ключей, их типов и меток enum находится в общем файле проекта `SIGNALS.md`.
- Единый источник истины — `signals.yaml`; файлы `CANDataReader.java`, `const.py` и `SIGNALS.md`
генерируются из него через `scripts/signals_tool.py`.

## Безопасность

- Cleartext HTTP разрешён для любых хостов (HA часто работает в LAN по `http://192.168.x.x:8123`, где HTTPS непрактичен) — см. `network_security_config.xml`. При отправке данных по HTTP на публичный адрес приложение пишет предупреждение в лог; для удалённого HA используйте HTTPS.
- Для продакшена используйте HTTPS и защищённый Long-Lived Access Token.
- Long-Lived Access Token HA хранится в Android Keystore через `SecureStorage`.
- Keystore и его пароли передаются только через переменные окружения (`KEYSTORE_FILE`, `KEYSTORE_PASS`, `KEY_ALIAS`, `KEY_PASS`) — не храните их в репозитории.
- Резервное копирование приложения отключено (`android:allowBackup="false"`), чтобы токен HA не попал в облачный бэкап.
- Директории `DiPlus-to-hass/build/` и `.keys/` создаются заново при сборке; не добавляйте их в git.

## Планы развития

- **Автоматические действия по правилам:** например, если температура за бортом выше 25 °C, автоматически включать обдув сидений на 100 % на местах, где сидят пассажиры.
